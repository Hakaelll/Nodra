Desde apps/mobile: flutter pub get, flutter analyze, flutter test. Emulador Android: flutter run --dart-define=API_URL=http://10.0.2.2:4000/api/v1. iOS Simulator usa http://localhost:4000/api/v1 en macOS. La API escucha en 127.0.0.1:4000 por defecto. Para Android físico en debug se puede activar `API_BIND_HOST=0.0.0.0`, restringir el puerto 4000 a la subred local y usar `flutter run --dart-define=API_URL=http://<IP-del-ordenador>:4000/api/v1` en una red privada. HTTP sin cifrar sólo está autorizado en el manifiesto Android de debug; iOS/distribución requieren HTTPS y configuración propia. No se ha validado aún en un segundo dispositivo. ## Aislamiento de sesión y contexto (02/11)

NodraApi mantiene una generación de sesión. Autenticar o limpiar sesión la cambia; las respuestas antiguas no pueden guardar credenciales, devolver datos ni reintentar una petición con la cuenta nueva. La renovación compartida pertenece a esa generación. Una cola propia ordena escrituras y borrados de tokens y de la preferencia de organización; descarta las operaciones que todavía no empezaron si su sesión quedó obsoleta.

SessionController sólo publica el resultado de la operación vigente. Recargar el perfil consulta la preferencia después de las escrituras pendientes. Cambios de organización simultáneos conservan el último tanto en memoria como en almacenamiento. La selección sigue limitada a las Memberships recibidas del backend; este control local no concede acceso.

Logout vacía inmediatamente el estado visible y limpia las credenciales y la preferencia local antes de intentar revocar el refresh remoto. Si no hay red, el cierre local permanece efectivo. No hay cola offline de revocaciones: una familia que no pudo revocarse permanece sujeta al vencimiento del backend. Un error de almacenamiento se propaga al llamador; el siguiente intento de escritura no queda bloqueado por la cola fallida.
